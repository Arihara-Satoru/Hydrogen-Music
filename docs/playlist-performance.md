# 歌单性能与回归验证

## 本轮优化

- 完整歌单读取：每页仍为 300 首，首批后最多并发 4 页；无数量提示时逐步增加并发。数量提示仅决定并发窗口，不作为结束条件，避免侧栏旧计数导致漏歌。
- 页结果按页码合并，保留重复歌曲、屏蔽过滤和原有列表排序。必要页失败会使整次读取失败；第一页面成功后不会切换到其他接口代替部分结果。
- 每次完整读取只调用一次本地歌曲哈希映射 IPC，不建立跨账号的持久歌单缓存。
- 搜索文本按需计算，以歌曲对象为弱引用键缓存 Vue computed；未搜索时不构建，歌曲元数据变更可自动失效。未筛选的详情页直接传递原歌曲数组。
- 喜欢状态使用共享 Set、歌曲别名使用 Map 索引；修改单首歌曲时增量维护记录索引。移除播放器和私人漫游中的重复状态应用。
- 写入成功后立即更新本地状态与列表，后台完整核验延迟 1500ms 合并；连续操作最多延迟 3500ms 发起核验（已有读取运行时需等待）。同版本同步复用进行中的读取，旧响应、账号切换和五秒本地操作保护保持有效。
- 缺少收藏歌单 fileid 时，删除所需的同步立即执行，不受后台合并延迟影响。

## 验证命令

```sh
npm run check:kugou-compatibility
npm run check:favorite-playlist
npm run bench:playlist
npm run build
```

基准使用模拟接口，不访问真实账号或写入真实歌单。每页模拟等待 10ms，测试环境为本机 Node，不能当作 Electron 首屏或真实酷狗网络耗时。

| 模拟场景 | 优化前样本 | 优化后样本 |
| --- | ---: | ---: |
| 648 首完整读取 | 52ms / 最大并发 1 | 30ms / 最大并发 2 |
| 10000 首完整读取 | 526ms / 最大并发 1 | 153ms / 最大并发 4 |
| 打开 10000 首歌单时搜索文本生成次数 | 10000 | 0 |
| 加一首时搜索文本生成次数 | 10001 | 0 |

基准耗时会波动，不能作为严格性能断言。单首插入仍需要复制当前歌曲数组并扫描重复项，是 O(n)，并未优化到 O(1)；本轮单次样本没有证明插入总耗时下降。首次搜索仍需计算搜索文本，后续搜索复用缓存。

回归测试还覆盖：分页乱序、并发上限、计数过期、整页屏蔽、重复歌曲、必要页失败、本地映射调用次数、搜索缓存失效、后台任务合并、连续操作最大等待、账号切换、旧响应保护和新 fileid 删除。

## 下一步边界

当前展示顺序涉及对完整结果反转，不能直接显示第一页后向末尾追加，否则会改变顺序。渐进首屏需要先确认真实上游排序协议、可靠总数和末页定位策略，或重新设计前后页插入及滚动锚点。

应在运行中的 Electron 中分别测量冷加载网络瀑布、歌曲规范化/状态同步、Vue 提交和首帧渲染，再决定是否引入渐进式加载、任务分片或有容量与账号隔离限制的缓存；不要直接取消服务端核验或去掉写入防缓存参数。
